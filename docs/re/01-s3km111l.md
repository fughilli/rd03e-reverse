# S3KM111L control interface (reconstructed from build 2268)

How the GD32E230 configures and reads the S3KM111L radar SoC. All function
addresses are in build 2268 (`targets/rd03e/2268_XenP102RM01.hex`); decompiled C
is in `out/2268/decomp/`, register evidence in `out/2268/mmio_accesses.csv`.
Confidence is HIGH for the transport/addressing/programming model below (direct
from decompiled register primitives); the concrete default register *values* are
not yet extracted (see Open items).

## Transport: I2C0 @ 1 MHz, device 0x40 (and 0x44)

The S3KM111L is an **I2C slave** on the GD32's **I2C0** master.

- **Bus:** I2C0 (`0x40005400`), pins **PB6 (SCL) / PB7 (SDA)**, clock **1 MHz**
  (Fast-mode Plus). Init in `FUN_08004758`; bus speed selected by
  `FUN_080046e8(4)` -> `0x000F4240` = 1 000 000. (It also knows 400 k / 300 k /
  200 k / 100 k.)
- **Device address:** **0x40** (7-bit) for the primary radar. A second device at
  **0x44** is programmed in lock-step whenever a "device count > 1" flag is set
  (`FUN_08001300`), i.e. the firmware supports a **two-SoC / dual-array** board.
- **Register model:** **8-bit register address, 16-bit register value,
  big-endian on the wire** (MSB first). The value is byte-swapped by the
  wrappers before/after the I2C transfer.

### Register access primitives (the chokepoints)

| Op | Fn | Signature (recovered) | Notes |
| --- | --- | --- | --- |
| **write reg** | `FUN_08004814` | `(dev, reg:u8, val:u16)` | swaps `val` to BE, `FUN_08004410(I2C0, dev, reg, buf, 2)` |
| **read reg** | `FUN_080047d8` | `(dev, reg:u8, *out:u16)` | `FUN_0800426c(I2C0, dev, reg, buf, 2)`, swaps BE->host |
| I2C master write | `FUN_08004410` | `(i2c, dev, reg, *data, len)` | START, addr+W, reg, data[], STOP (status-polled) |
| I2C master read | `FUN_0800426c` | `(i2c, dev, reg, *out, len)` | write reg, repeated-START, addr+R, read len |

So a single S3KM111L register access is: `START | dev<<1|W | reg | hi | lo | STOP`.

## Programming model: register tables

The radar is configured by **replaying tables of `{reg, value}` pairs**, not by
open-coded writes:

- **Boot table** — `FUN_08004cb8`: walks a table at **SRAM `0x20000010`**, 4 bytes
  per entry `[reg:u8][pad:u8][val:u16]`, calling `FUN_08004814(0x40, reg, val)`
  until the `val` field is 0 (terminator). Registers read/write function pointers
  (`0x08004815`, `0x080047d9`) are handed to `FUN_08004e84/70` first — a small
  HAL the radar code calls through.
- **Reconfig tables** — `FUN_08001300`: two tables at SRAM `0x200014c4` (len
  `*0x20001504`) and `0x20001508` (len `*0x20001548`), same 4-byte entry layout,
  written to **0x40** and, if `*0x200001c9 > 1`, also to **0x44**. Gated on a
  ready flag (`*0x200012bd`) and a mode index (`*0x200001ca`). This is the
  per-mode / per-profile reprogram path (e.g. switching ranging profiles).

The tables themselves live in **SRAM**, populated at boot from flash defaults
(and patched by calibration — `FUN_08003828` both reads and writes radar regs,
the classic read-modify-write calibration shape). The **concrete register
addresses/values are therefore not static constants in a single array** we can
dump directly; they are assembled at runtime.

## Open items (toward the actual register map)

- [ ] **Dump the default register set.** Find the flash source that initializes
      the SRAM tables (`0x20000010`, `0x200014c4`) — the `.data`/scatter-load
      copy or an explicit builder — and recover the `{reg,val}` defaults. The
      device addr (0x40), entry layout (`[reg][_][val:BE]`) and terminator (val
      ==0) are known, so this is a targeted extraction.
- [ ] **Name the registers.** Diff 2268 (ranging) vs 2269 (gesture): registers
      written in both = core bring-up; registers only one writes = mode config.
      Cross-with the Rd-01 (S3KM1110) protocol notes for field meaning.

      compile-time dead on a 1-device board).
